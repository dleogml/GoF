## 인터프리터(Interpreter) 패턴
- 요청을 캡슐화하여 호출자(invoker)와 수신자(receive)를 분리하는 패턴
- 자주 등장하는 문제를 간단한 언어로 정의하고 재사용하는 패턴
- 반복되는 문제 패턴을 언어 또는 문법으로 정의하고 확장할 수 있음
- 컴포짓 패턴과 유사한 구조를 띄게 됨(AST, Abstract Syntax Tree = 추상구문트리)


### 장단점
- 장점
  - 자주 등장하는 문제 패턴을 언어와 문법으로 정의할 수 있음
  - 기존 코드를 변경하지 않고 새로운 Expression을 추가할 수 있음
- 단점
  - 복잡한 문법을 표현하려면 Expression과 Parser가 복잡해짐

### 실무에서는 어떻게 쓰이나? 
- 자바의 Pattern라는 유틸 클래스에서 정규식과 매개변수를 가지고 매칭이 되는지 판별할 때 사용됨
- Spring에서는 SpEL(Spring Expression Language)라고 표현식 언어가 인터프리터 패턴의 대표적인 예시
